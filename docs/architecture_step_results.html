The adapters disagree

The package path is reclaimed, six modules are promoted, and all 17 report producers still reproduce exactly. The one thing that did not go to plan is the thing you asked to have checked: pi_models and pi_core do not produce the same Boltz-2.

Steps 1–3 are done and verified. Step 4 is blocked on a decision. Adopting pi_models as it is currently built would change the MSA regime from all 6,857 alignment rows to a random 1,024-row draw — which is exactly the property pi_core was configured to avoid. It costs 0.27 Å on expected distance, and it is a semantic change, not numerical noise.

It is fixable, and the fix is small. But it should be made and re-measured before pi_models becomes the collection path.

It is the MSA regime, and your own docstring predicted it

Introspecting the two built models:

pi_models wrapper.model.msa_module.subsample_msa = True, num_subsampled_msa = 1024
pi_core load_model(subsample_msa=False)

pi_core.load_model already says this in words — “deliberate and differs from mosaic's design-time default: for interpretability we need the MSA depth to be an exact, controlled quantity, not a random 1024-row draw that changes per key.” What is new is the price: 0.27 Å on expected distance.

It does not show up as an input difference, which is what makes it dangerous. Depth in the features matched at 6,857 on both sides; the subsampling happens inside the MSA module, downstream of featurisation, where a depth check does not look.

The confirming experiment: cap the alignment at 894 rows, below the 1,024 threshold, so there is nothing to subsample. The disagreement collapses.

Most of the gap was the draw. A residual remains at matched depth — 0.071 Å max, 0.003 Å mean — which is not the MSA and not the recycle count, and is not yet explained.

Fixable, but not through the constructor

Boltz2.__init__(self, cache_path: pathlib.Path | None = None) <- no MSA arguments
wrapper.model.msa_module is a frozen equinox Module

So the pi_models Boltz-2 factory has to replace the flag after construction with eqx.tree_at, rather than passing it in. That is the change I would make before adopting pi_models — then rerun this comparison and decide whether the remaining 0.003 Å mean is an acceptable tolerance or worth chasing.

What else changed

  • The package path is reclaimed. The May-era generation is gone — 41 package files including 14 MB of notebooks, plus the 11 scripts/ files that imported it, the 5 launchers whose drivers those were, and 9 tests. Recoverable with git show fcceb3f:<path>.
  • Six modules promoted — statistics, basis, chemistry, metrics, protocol, and the archive seam. Each keeps a six-line alias in jax_harness, so roughly 60 call sites work untouched and the move could be verified before anything was rewritten.
  • records.py exists now. pi_models has cited it as pi_schema.py since it was written; it had never existed in any commit. Its checks are the three models' real divergences — bin grids that differ while bin counts match, per-atom versus per-token pLDDT, the unsqueezed sample axis. 25 tests pass, all of them asserting a refusal.
  • A provenance bug, caught by the move. build_master_report hashed a flat list of jax_harness basenames as its code identity. After the promotion that would have hashed the six-line pi_protocol alias and reported it as the identity of every protocol block on the page. The list is repo-relative now.
  • checkout.sbatch runs the repository instead of the mirror, which is what verifying a moved library requires — and what the plan's acceptance test (“jobs submitted from a clean checkout”) already asked for.

Where this leaves the sequence

Steps 1 through 3 are complete and verified. Step 4 — unifying the adapters — now has a concrete blocker rather than an open question, which is the useful outcome: the equivalence check you asked for found something a code review would not have.

My recommendation is to make the eqx.tree_at fix, rerun exp_adapter_equiv.py, and treat the residual as the tolerance decision. If the residual survives at matched depth, it is worth understanding before pi_core stops being the thing that produces captures — it is 0.003 Å in the mean, but it is systematic, and the whole point of the shared basis is that small systematic shifts are what it measures.
