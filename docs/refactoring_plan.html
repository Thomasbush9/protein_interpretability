Architecture and migration plan · August 2026

From experiment history to an inspectable library

Refactor the protein-interpretability code into a clean library for representation collection, prediction, intervention, and offline analysis—while reproducing the inputs and results behind the current report across every tested model.

Planning document · no scientific result is considered migrated until old and new workflows agree under a recorded protocol.

1 · Goal and non-negotiable outcome

The finished repository should make a scientific experiment understandable from a short Python script. That script should state the model, inputs, representations, layers, interventions, measurements, and output location. Model-specific plumbing should remain available behind explicit, navigable methods, but should not obscure the experiment's surface behavior.

01
Library for all audited model backends
02
Clean separation between live model execution and offline analysis
03
Exact current cohorts and protocols preserved as manifests
04
Old and new results compared before legacy code is removed
Primary acceptance test. Starting from the recorded inputs used by the current report, the new library can recollect the required representations and reproduce the archived analysis outputs within declared numerical tolerances, using jobs submitted from a clean checkout.

Design rule

Experiment scripts describe scientific intent; library code handles model mechanics, capture, storage, validation, scheduling, and provenance.

Non-goals

  • Do not create one fictional architecture that hides meaningful differences among Boltz-2, OpenFold3, Protenix, AF2, and ESMFold.
  • Do not move datasets, model weights, MSAs, or large tensors into Git.
  • Do not rewrite validated numerical kernels merely to make the directory tree look uniform.
  • Do not delete historical scripts until an immutable external archive and a migration ledger exist.
  • Do not require a model environment to run offline analyses.

Stable concepts

ModelAdapter

Loads one architecture, builds features, exposes supported sites, executes predictions, and returns normalized outputs.

CaptureSpec

Names tensors, layers, recycling steps, reductions, precision, and expected memory without loading a model.

RepresentationArtifact

Versioned arrays plus tensor descriptors, model identity, input identity, resolved capture spec, and provenance.

AnalysisDataset

Reads artifacts only. It cannot import or instantiate a structure model.

Intervention

Defines a live alteration separately from the measurements collected after it.

ExperimentContext

Resolves paths, seeds, environment, output identity, SLURM metadata, and resume policy once.

Adapter contract

  • Report architecture name, implementation/backend, checkpoint identity, layer count, channel widths, and output grids.
  • Expose supported capture sites as data; invalid layer/site combinations fail during inspection.
  • Accept an explicit local input/MSA manifest and report exactly what was consumed.
  • Normalize common outputs without normalizing away architecture-specific semantics.
  • Prevent silent network fallback during reproduction runs.
  • Keep native numerical behavior unchanged until equivalence has been established.

Reproduction guard. A job must stop if a checksum, residue/token mapping, MSA depth, model grid, or expected representation width differs from the manifest. It must never regenerate or substitute an input silently.

6 · The inspectable surface

The preferred user interface is Python. YAML may provide paths and cohort data, but the scientific behavior should remain visible in a short program.

Collection

from protein_interpretability.collection import (
    CaptureSpec,
    Cohort,
    ModelCollector,
)

cohort = Cohort.from_manifest("configs/cohorts/cross_model_assays.yaml")

capture = CaptureSpec.pair_representations(
    layers="all",
    at_mutation_site=True,
    recycle="final",
)

collector = ModelCollector.for_model(
    "boltz2",
    backend="joltz",
    recycles=3,
    seed=0,
)

collector.collect(
    cohort,
    capture=capture,
    output="runs/boltz2_pair_layers",
)

Offline analysis

from protein_interpretability.analysis import (
    RepresentationDataset,
    SharedBasis,
    leave_one_assay_out,
)

reps = RepresentationDataset.open("runs/boltz2_pair_layers")
dz = reps.difference_from_reference(
    field="pair",
    reduction="mutation_row_mean",
)

basis = SharedBasis.fit(
    dz,
    standardize="within_assay",
    center=True,
    orient_by="model_divergence",
)

result = leave_one_assay_out(
    basis.project(dz, components=[1]),
    target="assay_score",
)

Prediction

from protein_interpretability.collection import Cohort
from protein_interpretability.prediction import Predictor

cohort = Cohort.from_manifest("configs/cohorts/cross_model_assays.yaml")
predictor = Predictor.for_model("openfold3", recycles=3, seed=0)

predictor.predict(
    cohort,
    outputs=["distogram", "plddt", "coordinates"],
    output="runs/openfold3_predictions",
)

Intervention

from protein_interpretability.intervention import (
    PairDirectionIntervention,
    DistogramWidth,
    PLDDTAtSite,
)

intervention = PairDirectionIntervention.from_artifact(
    "artifacts/shared_basis_v1",
    component=1,                # zero-based PC2
    layers=["final"],
    mode="symmetric_row_column",
    doses=[-30, -10, -3, 3, 10, 30],
)

collector.intervene(
    cohort,
    intervention=intervention,
    measurements=[DistogramWidth(), PLDDTAtSite()],
    controls={"random_directions": 8, "seed": 0},
    output="runs/heldout_pc2_intervention",
)

Command-line lifecycle

# Login node: parse and validate only; never load a model.
uv run pi collect inspect experiments/collection/collect_pair_layers.py

# Render the exact resolved job and resource estimate.
uv run pi collect render experiments/collection/collect_pair_layers.py

# Submit the resolved job to SLURM.
uv run pi collect submit experiments/collection/collect_pair_layers.py

# Compute node / allocation only.
uv run pi collect run experiments/collection/collect_pair_layers.py

# Offline analysis can run without any model environment.
uv run pi analyze run experiments/analysis/reproduce_transfer.py

7 · Migration sequence

The migration proceeds as vertical slices. Each slice must produce a readable experiment, a reusable artifact, an offline analysis, and an old-versus-new comparison before the next more complicated workflow is attempted.

Freeze and inventory

Record the repository commit, archive source, enumerate scripts and archives, checksum inputs, and build the model/input/result migration ledger.

Schemas and dry run

Implement manifests, CaptureSpec, artifacts, adapter metadata, site profiles, inspection, and SLURM rendering without model execution.

Boltz-2 vertical slice

Migrate final/per-layer pair capture and WT–variant differences. Reproduce one small fixture and one existing assay.

Offline analytical core

Migrate shared basis, transfer probes, chemistry/output baselines, bootstraps, permutations, and protocol-aware result writing.

Cross-model adapters

Migrate OpenFold3 and Protenix using identical cohort/MSA manifests; reproduce the four-assay cross-model and depth panels.

Prediction and intervention

Separate normalized prediction outputs, then migrate PC2 steering, random controls, doses, sites, and response metrics.

Additional models

Audit and migrate AF2 and ESMFold, documenting which common contracts apply and which representation semantics remain model-specific.

Archive and remove

Classify every old script, verify its replacement or historical status, archive with checksums, then remove legacy scope from the active tree.

First reference slice

The first implementation milestone should contain two programs and one small cohort:

experiments/collection/collect_pairformer_layers.py
experiments/analysis/analyze_pairformer_layers.py
configs/cohorts/smoke_pairformer.yaml

It should reproduce the capture and derived layer trace currently implemented through the Joltz harness, while leaving the tested numerical capture functions unchanged behind the new adapter.

Unit and contract tests

  • Manifest and config parsing
  • Site/layer validation
  • Schema round trips
  • Memory estimates
  • Analysis on synthetic arrays
  • SLURM rendering

Model smoke tests

  • One short sequence
  • Minimal recycles

  • No unnecessary diffusion
  • Old/new capture comparison
  • Offline/no-network enforcement
scientific

Regression tests

  • Tensor shapes and dtypes
  • Hashes or numerical summaries
  • Mutation-site dz
  • Basis components and orientation
  • Probe statistics and intervals
  • Figure input tables

Comparison hierarchy

  1. Input equivalence: same sequence, MSA content/depth, residue mapping, checkpoint, seeds, recycles, and model settings.
  2. Execution equivalence: same capture site semantics, tensor shape/dtype, output grid, and deterministic settings.
  3. Representation equivalence: arrays equal or within a justified backend-specific tolerance.
  4. Derived-feature equivalence: same dz_site, layer reductions, prediction summaries, and basis projections.
  5. Statistical equivalence: same splits, normalization, feature width, seeds, permutation units, estimates, and intervals.
  6. Report equivalence: each current report input can be regenerated and the headline tables remain within declared tolerances.

9 · HPC execution contract

  • inspect and render never import a model backend or initialize CUDA/JAX.
  • GPU runs refuse to execute on a login node unless an explicit development override is present.
  • SLURM scripts are generic; account, partition, memory, time, GPUs, cache roots, and container paths come from a site profile.
  • Temporary processing uses job-local scratch; final artifacts are atomically committed to shared storage.
  • Capture memory is estimated before submission, with reduced mutation-row captures preferred over full N × N × C × L tensors.
  • Completed records are resumed only after validating their artifact metadata and checksums.
  • Network access is blocked for reproduction jobs that claim to use fixed local MSAs.
  • Each model may use its required environment/container, while artifacts obey one versioned storage contract.
  • UV_CACHE_DIR and other caches resolve to writable job-local or configured paths rather than a login-node home cache.
  • Logs record resolved configuration, host, job ID, device, environment identity, Git commit, and input manifest hash.

10 · Definition of done

  • The exact original, held-out, cross-model, and intervention cohorts are represented by checksummed manifests.
  • Boltz-2, OpenFold3, and Protenix reproduce the current report inputs through supported adapters.
  • AF2 and ESMFold are either supported through the same contracts or explicitly documented as audited exclusions with reasons.
  • Collection, prediction, intervention, and analysis have separate import boundaries and artifact contracts.
  • Offline analysis installs and runs without model-specific environments.
  • Every supported workflow has a short Python experiment that exposes its scientific choices.
  • Every live run has a login-node-safe inspection path and a scheduler submission path.
  • Current headline result families pass recorded old-versus-new regression checks.
  • All active result writers enforce protocol and provenance metadata.
  • The migration ledger accounts for every old harness and script file.
  • Historical code has been copied to an immutable external archive with checksums.
  • Legacy code is removed from the active repository only after the preceding conditions pass.
First deliverable. Implement the schemas and dry-run path, then migrate the Boltz-2 pair-layer vertical slice into collect_pairformer_layers.py and analyze_pairformer_layers.py. Use that slice to judge whether the public API is genuinely easy to inspect before applying it to the remaining experiments.
